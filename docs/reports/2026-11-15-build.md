## 3. Cách bạn kiểm tra (khoảng 10 phút)

**Bước 0 — đăng nhập lại Claude CLI** (chỉ bạn làm được): mở terminal, chạy `claude`, rồi gõ `/login`.

**Bước 1 — cài plugin** (hoặc bỏ qua bước này và dùng `--plugin-dir` để thử mà không cài):

```bash
claude plugin marketplace add Quannguyen830/harness
```
```bash
claude plugin install harness@harness
```

**Bước 2 — tự xem một vòng trên sandbox.** Repo [harness-sandbox](https://github.com/Quannguyen830/harness-sandbox) (private) đã đi xong feature 001 (mục 4b). Bạn mở một feature mới ở đó:

```bash
cd D:/Driver_D/harness-sandbox
```
```bash
claude --plugin-dir D:/Driver_D/harness
```

Trong phiên Claude:

1. `/harness:next add a --lines flag that also counts lines` → agent grill bạn. Trả lời như bình thường, rồi nói "clear enough".
2. `/harness:next` → agent viết spec và dừng ở Gate A. Đọc spec, rồi nói "approved".
3. `/harness:next auto` → agent làm task, mở PR, dừng ở Gate B.
4. Comment vào một PR trên GitHub, rồi chạy `/harness:next` → agent áp feedback (sửa docs trước) và ghi `docs/interventions.md`.
5. Merge hết các PR, chạy `/harness:next` → agent hỏi fit score.

Ở lần chạy thử, agent luôn gọi đúng `harness:*` và `${CLAUDE_PLUGIN_ROOT}` được thay đúng đường dẫn. Mọi chỗ bạn phải can thiệp thì ghi vào `docs/interventions.md`; đó là số liệu thật đầu tiên.

### 4b. Lần chạy thật trên sandbox

| Bước | Kết quả |
|---|---|
| `/harness:next <idea>` | Gọi đúng `harness:grill`; `new-feature.mjs` tạo thư mục; mỗi round 5 câu, ghi vào `grill.md`; commit `docs: grill` thẳng vào master |
| `/harness:next` | `harness:spec` viết 12 tiêu chí EARS, 2 seam, T2 phụ thuộc T1; `check-spec` pass; dừng ở Gate A |
| "approved" | Đổi `Status: approved`, commit |
| `/harness:next auto` | Làm T1 theo TDD, mở PR #1, **dừng ở Gate B** vì T2 phụ thuộc T1 (đúng thiết kế) |
| Comment trên PR | `/next` nhận ra bước `feedback`; G5 thêm test, ghi `docs/interventions.md` (tự xếp loại `agent-mistake`), reply `[harness]`; `/next` quay về Gate B |
| Merge #1 → auto | T2 → PR #2 → Gate B |
| Merge #2 → `/next` | Bước `done`, hỏi fit score, đóng feature; `/next` về `idle` |

**Bug tìm được, đã sửa ở PR #12:** sau squash-merge, nếu agent vẫn đứng trên branch task cũ và master local chưa pull, `/next` báo bước `pr` cho task đã merge. Đã sửa ba chỗ: `/next` fetch remote và đọc spec từ `origin/master`; bỏ qua branch của task đã tick trên master và báo `cleanup`; skill `pr` quay về master sau khi mở PR.

**Hai bài học đưa vào harness ngay:**
- Skill execute: test phải viết ký tự vô hình dạng escape (bài học từ dòng intervention đầu tiên).
- Slug bỏ stopword: `a-cli-that-counts-words` thành `cli-counts-words-text-file`.

**Vướng ngoài harness:**
- Định dạng "✅ TASK COMPLETE" trong CLAUDE.md global của bạn lọt vào output của execute (cộng thêm lý do cho mục 7.6).
- Một hook của máy chặn lệnh shell có ký tự Unicode whitespace.
- Phiên con dùng tool PowerShell mặc định, nên khi chạy headless phải tắt tool đó.

Số liệu: [benchmarks/2026-11-15-smoke-harness-sandbox.md](../../benchmarks/2026-11-15-smoke-harness-sandbox.md), khoảng $6 usage và 25 phút. Đây là bài kiểm tra máy móc, không phải benchmark chất lượng.

**Một bug thật được test tìm ra:** khi verify là `node --test` và chính hook chạy bên trong một test runner, biến `NODE_TEST_CONTEXT` bị kế thừa nên test con luôn báo pass. Đã sửa trong #10.

## 5. Quyết định mình tự đưa ra — cần bạn duyệt

1. **Docs của feature** (grill, spec, duyệt spec, fit score) **commit thẳng vào `master`**. Code thì luôn đi qua branch task và PR. Đã ghi vào spec §4.5.
2. **Feature được đóng** khi mọi task đã tick **và** cuối spec có dòng `Fit score: N — ...`. Đã ghi vào spec §4.5.
3. **Duyệt ở Gate A:** bạn sửa `Status: approved`, hoặc chỉ cần nói "approved" để agent sửa và commit.
4. **Mỗi round grill tối đa 5 câu.** Matt hỏi toàn bộ frontier một lượt; mình giới hạn để bạn trả lời nhanh.
5. **Phát hiện feedback:** comment hoặc review mới hơn commit cuối của PR. Agent trả lời bằng comment có tiền tố `[harness]`, để `/next` không coi đó là feedback mới.
6. **Stop hook bỏ qua thay đổi chỉ trong docs** (`docs/`, `*.md`), để không chạy test sau mỗi lượt grill.
7. **`/next <idea>` bị từ chối khi đang có feature mở.** Muốn mở feature mới thì phải xong hoặc gác feature hiện tại.
8. **TDD lấy của Matt, không lấy của superpowers.** Từ superpowers chỉ lấy nguyên tắc "evidence before claims". Phần visuals trong skill `pr` của Matt có credit cho humanlayer (`show-me`); mình chưa kiểm license của nó nên không copy phần đó.
9. **`domain-modeling` ghi ADR vào `docs/decisions.md`** chứ không vào `docs/adr/`, để mỗi project chỉ có một log quyết định.
10. **Tên lệnh:** `/harness:next`, hoặc `/next` nếu không trùng tên với lệnh khác.
11. **Merge PR qua GitHub API.** Hook git-safety đã tắt trong settings, nhưng session của mình nạp nó từ lúc mở nên vẫn chặn `gh pr merge`. Bạn đã cho phép tự merge, nên mình dùng `gh api .../merge`. Cũng vì hook cũ đó, commit `.gitattributes` đi qua PR #1 thay vì commit thẳng.
12. **Repo public, license MIT.** Các component mượn về giữ license gốc trong `vendor-licenses/`.

## 6. Chưa làm, rủi ro, việc tiếp theo

- **Bản chạy thử do Claude đóng vai bạn,** nên chưa đo được chất lượng thật. Con số thật sẽ đến từ dogfood habit tracker, khi bạn lái. Mục 3 vẫn hữu ích nếu bạn muốn tự xem một vòng.
- **Bạn không chặn được** việc agent chọn nhầm skill trùng tên, chừng nào `mattpocock-skills` còn bật. Việc này thuộc v0.3.
- **`selftest` chỉ bắt được trùng *tên*,** không bắt được hai component trùng *việc* nhưng khác tên. Việc đó vẫn cần bạn review.
- **Phát hiện feedback dựa vào thời gian commit.** Nếu commit bị rebase hoặc giờ máy lệch thì có thể sai; khi đó `/next` sẽ bỏ sót hoặc báo thừa một lượt feedback.
- **Body của PR #8 ghi "41/41"; số đúng là 40/40.** Lỗi trong mô tả, không ảnh hưởng code.
- **v0.3 (dọn máy) chưa làm gì,** đúng như bạn dặn. Danh sách đề xuất ở mục 7.

## 8. Đo lường từ đây

- Mỗi project có `docs/interventions.md`. Agent ghi nháp từ chat và từ comment PR, bạn xác nhận. Loại can thiệp chia theo lỗi của ai.
- `node scripts/collect-logs.mjs <project> --out benchmarks/<date>-greenfield-<project>.md` tính: error rate, điểm nghẽn theo gear, first-pass merge, số vòng G5 trên mỗi PR, fit score, kèm version harness.
- Con số thật đầu tiên sẽ đến từ bước kiểm tra ở mục 3, rồi từ dogfood habit tracker. Nhớ tag harness (`v0.2.0` đã có) trước mỗi lần chạy.
